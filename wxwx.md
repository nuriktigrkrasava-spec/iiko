## Контекст

Продукт — **ИИ-финдиректор ресторана для ВСЕХ сетей** (мультитенант), не для одной.
Светлый премиум-редизайн живёт в `web/` (React+Vite+TS, точка входа `web/src/lg/LiquidApp.tsx`).
Бэкенд — `api.py` (FastAPI, iikoServer/iikoWeb REST для аналитики) + `insights_service.py`
(:8010, Директор-оценка) + `iiko.py` (клиенты: `IikoWebClient` resto/api и `IikoClient` iiko Cloud).
Старый прод-мини-апп — `index.html` (чёрный, Telegram) — **не трогаем**, в долгую сводим к
одному адаптивному фронту.

## Как запустить на РЕАЛЬНЫХ данных (локально)

```
# .env содержит ENCRYPTION_KEY; локальная iiko_boss.db содержит филиалы владельца
ENC=$(grep '^ENCRYPTION_KEY=' .env | cut -d= -f2- | tr -d '"')
# бэкенд (без TELEGRAM_BOT_TOKEN → dev-авторизация; DEV_TID = владелец)
DEV_TID=8727082281 ENCRYPTION_KEY="$ENC" DB_PATH="$PWD/iiko_boss.db" .venv/bin/python -m uvicorn api:app --port 8000
DEV_TID=8727082281 ENCRYPTION_KEY="$ENC" DB_PATH="$PWD/iiko_boss.db" .venv/bin/python -m uvicorn insights_service:app --port 8010
# фронт: реальные данные — БЕЗ VITE_BAKED (проксирует /api→:8000, /api/insights→:8010)
cd web && npm run dev            # :5180 = реальные данные
cd web && VITE_BAKED=1 npm run dev   # :5181 = офлайн-демо
```

- **Dev-авторизация:** `get_current_user` — без init-data и без BOT_TOKEN берёт `DEV_TID` → действуем как владелец, видим его реальные филиалы. В проде — обычная Telegram-авторизация.
- Владелец = TID `8727082281`, api_login `nignarok`, сервер `saya-co.iiko.it` (resto), 13 филиалов.
- **iiko Cloud apiLogin** (живой зал) владельца сохранён в `restaurants.cloud_api_login` (шифр.) — только для локального теста. 25 Cloud-организаций; Cloud-org ID ≠ resto-org ID (маппинг по названию).
- Проверять: `npx tsc -b` в `web/` + глазами (playwright/скрин).

## 🐞 БАГИ с реальных тестов (приоритет — сверху)

**Сквозной принцип (важно):** если у клиента что-то НЕ заполнено в iiko (техкарты/себестоимость,
соцсети, и т.п.) — ИИ-агент/Директор должен ставить это **ПЛАНОМ** («заполни техкарты, чтобы
считать фудкост»), а не показывать 0/пусто/демо.

1. **Демо-данные при подключённом ресторане** — убрать. При LIVE-филиале всё ещё демо: Home KPI «Оборот стола / Лист ожидания / Бронь на вечер» (константы), лента «Активность» (`feed`), план недели в Widgets (`WEEK`), ответы агента (`Agent.reply`), часть плана/пути Директора. → При `real` прятать демо или «нет данных»+план.

2. **Столы разъезжаются** (`Home.tsx` TableTop/mapping). Реальные координаты из Cloud-схемы (x/y px → %) ложатся криво: у части столов координат нет (fallback-грид) или sw/sh/наклон rotateX сбивают раскладку. → Рисовать по реальной схеме секции (width×height) корректно; аккуратный фоллбэк для столов без координат.

3. **ИИ-помощник отдаёт демо** — `Agent.tsx` `reply()` = хардкод («фудкост 36%…»). → Агент должен отвечать по РЕАЛЬНЫМ сигналам филиала (тянуть /api/insights,/api/foodcost и т.д.), а при отсутствии данных — ставить план. (LLM опционально.)

4. **«Посадка зала — источник не подключён»** — `Director.tsx` `noData = ['Посадка зала','KDS','Соцсети']` захардкожено. Зал теперь подключён (Cloud) → убрать «Посадка зала» из noData / определять динамически по `has_cloud`.

5. **У всех одинаковые планы / отмены / отзыв Wolt** — часть экранов ещё демо или период/org не прокидывается; reviews демо. Фудкост без техкарт не считается — **это нормально**, но должно превращаться в план (см. 7). → Проверить, что все экраны берут данные по выбранному org и не отдают общий демо.

6. **Фильтры времени не работают** — период (LiquidApp `period` state) НЕ прокидывается в `useApi` экранов (каждый фетчит со своим `{period:'month'}`). → Прокинуть общий период (контекст/проп) во все useApi + перезапрос при смене.

7. **Фудкост пуст без техкарт** (`screens.tsx` FC, `Director` структура). → Если техкарт/себестоимости нет — показать план «заполнить техкарты, чтобы считать фудкост» (ИИ-агент ставит планом), а не пустой экран.

8. **Способы оплаты в «млн ₸»** — `Menu.tsx` `payData` делит на 1_000_000 и юнит ' млн' — нечитабельно. → Показывать `tengeShort(revenue)`, убрать деление/«млн».

9. **В накладных нет позиций** — `/api/invoices` (api.py) мапит `positions` из `inv.items`, но реальные поля iiko invoiceIncomings другие → позиции пустые/нули. → Проверить реальный формат items (ключи product/amount/price/sum) и поправить маппинг.

10. **Склад: `stock: HTTP 400`** — `/api/stock` на реале отдаёт 400. → Найти endpoint `/api/stock` в api.py, разобрать причину (параметры/OLAP/balance stores).

11. **Расписание — нет изоляции филиалов** — `/api/attendance` возвращает ВСЕХ сотрудников сети, не по выбранному филиалу. → Фильтровать по org. И показывать уже существующее расписание сотрудников (не верю, что у всех пусто).

12. **Кнопка «Подключить» соцсети не работает** — `Reputation.tsx` кнопки без обработчика.

13. **«Что улучшилось за неделю» — только 0 / нет данных** — на реале `comparison` пуст. → Если данные не заполнены в iiko — агент ставит план, а не показывает 0.

14. **Пропал бар «Куда уходит выручка»** — `Director.tsx` `costLines` строится только если `revenue>0 && fcd` (foodcost fact_pct). На реале без техкарт fact_pct=None → revenue=0 → блок скрыт. → Фоллбэк/план когда нет фудкоста.
