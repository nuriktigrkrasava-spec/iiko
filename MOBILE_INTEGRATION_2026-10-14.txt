Интеграция мобильного «Финдиректора» — кандидат, не production

1. Применять после review, backup БД и проверки на отдельном staging. Production-секреты, домен, диск и webhook не менялись.
2. Сотрудники: NATIVE_STAFF_ENABLED=1, NATIVE_JOIN_ENABLED=1 только после настройки NATIVE_APP_ORIGIN (HTTPS origin без пути) и тестового Telegram-бота. В выключенном состоянии config сообщает enabled:false. Проверить первичную привязку, подтверждение, срок, выход, отзыв и смену филиала.
3. Уведомления: установить requirements-push.txt; отдельный сервисный аккаунт Firebase с разрешением отправки FCM, файл вне репозитория. FIREBASE_PROJECT_ID=findirector; FIREBASE_SERVICE_ACCOUNT_FILE — закрытый путь; ENCRYPTION_KEY — действующий ключ; PUSH_ENABLED=1 только после теста. Без конфигурации доставка выключена. iOS APNs ещё не настроен; мобильный переключатель включён только для Android-управляющих.
4. HTTPS-серверы iiko вне *.iiko.it: IIKO_TRUSTED_HOSTS, точные имена через запятую. Дополнительные источники CSV: CSV_TRUSTED_HOSTS. Не разрешать непроверенные домены. Проверить существующие сертификаты; не отключать TLS ради совместимости.
5. Старые ключи Telegram/Anthropic/GitHub/RMS должны быть отозваны владельцем. Замена ENCRYPTION_KEY без миграции зашифрованных данных недопустима. При прежнем резервном ключе личные ссылки перевыпустить по согласованному плану.
6. На staging: два независимых владельца A/B, управляющий A, сотрудник A. Проверить чтения и записи с подставленными ID B; отклонение без побочных действий. Сверить суммы с тестовым iiko, накладные, акты, явки и повтор после обрыва сети. Боевые финансовые операции не использовать для проверки.
7. Native auth создаёт собственные таблицы при первом включении. Push создаёт таблицу привязок; не выполняет очистку бизнес-данных. Все миграции сначала проверить на копии БД.
8. App Links/Universal Links отдельно требуют файлов ассоциаций на вашем домене и действительных сертификатов приложения. В этом PR домен и Apple capabilities не настраивались.
