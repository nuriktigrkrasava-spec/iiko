# Дизайн: Сводка расходов для бухгалтера (Excel/CSV)

**Дата:** 2026-07-01
**Ветка:** feat/demo-trial (продолжение)
**Статус:** утверждён владельцем, готов к плану

## Контекст и мотивация

Денежные расходы (зарплата, аренда, коммуналка, маркетинг) **нельзя записать в iiko
извне** — ни через REST API, ни через файловый импорт iikoOffice (подтверждено
ресёрчем: cash/account типы 404 в API; importCsv.jsp принимает только справочники и
товарные документы). iiko намеренно держит ввод денег в iikoOffice (человек) и на
кассе. Товарные расходы (закупки) в iiko уже попадают — через существующую фичу
накладных.

Поэтому вместо несуществующей автозаписи делаем **помощник бухгалтеру**: бот
выгружает ручные расходы (которые уже лежат в его БД) удобной сводкой, по которой
бухгалтер за пару минут вносит их в iikoOffice по нужным счетам.

## Зафиксированные решения

- **Форма:** кнопка **«📄 Сводка для бухгалтера (Excel)»** на вкладке Расходы
  (суб-вкладка «Ручные») + блок-справка «как с этим работать».
- **Только фронт** (`index.html`): новый тип в `exportReport(type)` + кнопка +
  инфо-блок. Бэкенд не трогаем (экспорт в проекте клиентский — собирает CSV из уже
  загруженных данных, разделитель `;`, BOM `﻿` для Excel-ru).
- **Источник данных:** `state.expensesData` (загружается в `loadExpenses`), берём
  операции с `type === 'manual'` за текущий период.
- **Не автозапись** в iiko (её не существует) — только выгрузка + инструкция.
- **Общий Mini App:** демо-бот и основной бот используют один `index.html`, поэтому
  сводка автоматически доступна и в 24ч-триале демо-бота. Кнопку НЕ гейтить под
  `DEMO_ONLY`/триал — она должна работать у всех, у кого есть ручные расходы.

## Содержимое выгрузки (CSV, открывается в Excel)

Один файл `bookkeeper-expenses.csv`, три секции (разделены пустой строкой):
1. **Сводка по категориям:** `Категория;Сумма` — по убыванию суммы, + строка «ИТОГО».
2. **Детально:** `Дата;Категория;Сумма;Комментарий` — все ручные расходы за период.
3. **Справочник счетов iiko** (справочно): `Расходный счёт iiko` — список счетов
   заведения: «Прочие расходы», «Расход продуктов», «Маркетинговые расходы»,
   «Коммунальные расходы», «Расходы и ремонт на авто» (константа во фронте; на этапе
   реализации можно вынести в конфиг, но для MVP хватает статичного списка, полученного
   с сервера Saya через probe).

Маппинг «категория → счёт iiko» **не жёсткий** (категории свободные): даём
сгруппированные суммы + справочник счетов, бухгалтер сопоставляет сам. Так честнее,
чем угадывать.

## Справка в суб-вкладке (инфо-блок)

Короткий текст рядом с кнопкой:
> 💡 Денежные расходы (зарплата, аренда, коммуналка) iiko не принимает автоматически —
> в отличие от накладных на товар. Порядок: скачайте сводку → бухгалтер вносит расходы
> в iikoOffice по указанным счетам. Категории уже сгруппированы.

## Компоненты (index.html)

- Разметка суб-вкладки «Ручные» (в `#tab-expenses`): кнопка «📄 Сводка для бухгалтера»
  + инфо-блок с текстом выше.
- `exportReport('expenses-bookkeeper')`: новая ветка — фильтрует `state.expensesData`
  по `type==='manual'`, группирует по категории, собирает CSV из трёх секций, скачивает
  тем же механизмом, что и остальные экспорты (`downloadCsv`/Blob в конце `exportReport`).

## Краевые случаи

- Нет ручных расходов за период → тост «Нет ручных расходов за период» (файл не качаем).
- Категория пустая → «Без категории».
- Суммы округляем до целых (как в `formatMoney`), разделитель `;`, префикс BOM.

## Не входит

- Автозапись расходов в iiko (невозможна технически — см. контекст).
- Жёсткий маппинг категорий на счета (категории свободные).
- Изменения бэкенда.
