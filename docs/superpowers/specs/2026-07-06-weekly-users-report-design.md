# Еженедельный отчёт юзерам + выручка в ночной сводке

Дата: 2026-07-06. Одобрено владельцем («норм давай делай»).

## Что делаем

Сетка авто-отчётов для ВСЕХ юзеров бота с подключённым iiko (демо и прод —
код общий, БД разные):

### 1. Ежедневно (ночная сводка смен — обогащаем, новое сообщение НЕ шлём)

К существующей сводке `_send_daily_shifts_report` добавляется строка:

```
💰 Выручка вчера: 342 000 ₸  🟢 ▲ +9% к прошлой субботе
```

Сравнение — с тем же днём недели неделю назад (суббота к субботе),
чтобы не было ложных «падений» после выходных. Выручка = кассовые смены
(payOrders), суммарно по всем филиалам владельца.

### 2. Еженедельно, понедельник после REPORT_HOUR_LOCAL (10:00) — новое

Каждому владельцу по каждому его филиалу за прошлую полную неделю (пн–вс)
против позапрошлой:

```
📊 Итоги недели (29.06–05.07)
сравнение с прошлой (22.06–28.06)

🏢 Чашка
   Выручка: 2 150 000 ₸  🟢 ▲ +12% (+230 000 ₸)
   Средний чек: 4 850 ₸  🔴 ▼ −3%
   Гости: 443  🟢 ▲ +8%
   ⚠️ Проблемы за неделю:
   • 2 смены с расхождением кассы (−12 500 ₸)
   • 3 исправленных платежа (1 со сменой типа оплаты)
   • 1 непринятая смена
```

Без проблем — «✅ Смены чистые, расхождений нет».

## Технически

- Выручка недели — из кассовых смен (payOrders, `_branch_sessions`), как в
  дашборде; фолбэк на OLAP (`_branch_week_metrics`), если клиент облачный
  или смены не сузились до филиала. Гости — всегда OLAP; ср. чек =
  выручка/гости.
- Проблемы: cashDiff ≠ 0, sessionStatus ≠ ACCEPTED, исправленные платежи —
  `get_cashshift_payments` + `_payment_edits` по каждой смене недели.
- Новый цикл `_weekly_users_report_scheduler`: weekday()==0, час ≥
  REPORT_HOUR_LOCAL, дедуп через app_state `weekly_users_last_sent`
  (переживает рестарты Render) — по образцу существующих шедулеров.
- Превью: `GET /api/weekly-user-report/preview` — юзер видит СВОЙ отчёт
  (авторизация через X-Telegram-Init-Data), `send=true` — прислать себе.
- Воскресный отчёт ген.директору не трогаем.
