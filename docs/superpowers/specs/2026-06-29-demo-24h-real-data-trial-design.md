# Демо-бот: 24-часовой триал с реальными данными — дизайн

Дата: 2026-06-29
Прод-ветка: `deploy-cashshifts` (демо-сервис `iiko-demo`, env `DEMO_ONLY=1`)

## Цель

В демо-боте (@wiredemobot) дать проспекту **полный доступ к ЕГО реальным данным
в Mini App на 24 часа** после того, как он подключит свой iiko прямо в чате.
По истечении суток — **жёсткий замок** + продающий экран (разработка 200 000 ₸ +
подписка). Это сильнейший хук: владелец видит свои настоящие цифры и хочет
оставить доступ.

## Контекст / факты кода

- `DEMO_ONLY=1` на демо-сервисе → `_is_demo_user(user)` (api.py:902) всегда True.
- ~26 аналитических эндпоинтов гейтят данные одинаково:
  `if _is_demo_user(user) or org_id == "demo-org-1": return DEMO_*` (api.py:1039,
  1124, 1226, 1343, 1401, 1472, 1519, 1611, 1696, 1759, 1863, 1953, 2032, 2060,
  2091, 2153, 2163, 2386, 2401, 2631, 2648, 2728, 2765, 2987, 3030, 3048).
- Подключение iiko в чате уже есть: `_handle_demo_registration` (api.py),
  сохраняет реальные org+creds через `add_restaurant` (database.py:289,
  шифрует пароль). `_get_user_orgs(tid)` = `get_restaurants(tid)` (не демо-гейт).
- `list_restaurants` (api.py:831-region) на демо-боте вернёт реальный филиал, если
  он сохранён (иначе `[DEMO_RESTAURANT]`).
- `/api/config` (api.py:831) — БЕЗ авторизации, отдаёт `{demo_only}`.
- Фронт демо: `initApp` → `if (demoOnly) { startDemo(); return; }` (всегда демо,
  org `demo-org-1`). `startDemo()` ставит `state.demoMode`, грузит демо-ресторан.
- Лимит распознавания: `demo_invoice_usage` (database.py:128) — модель для новой
  таблицы триала.

## Архитектура

Центральная идея: триал = «временное снятие демо-гейта для аналитики». Вводим
один helper, который решает, отдавать ли демо-данные, и хранит 24ч-окно.

### 1. Данные (database.py, БД демо-сервиса)

Новая таблица (один ряд на пользователя, повторное подключение НЕ перезапускает):
```sql
CREATE TABLE IF NOT EXISTS demo_trial (
    telegram_id INTEGER PRIMARY KEY,
    org_id      TEXT,
    started_at  TEXT
);
```
Helpers:
- `start_demo_trial(telegram_id, org_id)` — `INSERT OR IGNORE` (первое подключение
  фиксирует старт; повтор не сбрасывает).
- `get_demo_trial(telegram_id) -> Optional[dict]` — `{org_id, started_at}` или None.
- `init_demo_trial_db()` — создание таблицы, вызвать в `startup`.

### 2. Логика триала (api.py)

Конфиг: `DEMO_TRIAL_HOURS = int(os.getenv("DEMO_TRIAL_HOURS", "24"))`.

```python
def _demo_trial_state(telegram_id: int) -> dict:
    """state: none | active | ended; + expires_at, hours_left, org_id."""
    row = get_demo_trial(telegram_id)
    if not row or not row.get("started_at"):
        return {"state": "none"}
    started = datetime.fromisoformat(row["started_at"])
    expires = started + timedelta(hours=DEMO_TRIAL_HOURS)
    now = local_now().replace(tzinfo=None) if started.tzinfo is None else local_now()
    active = now < expires
    secs_left = max(0, int((expires - now).total_seconds()))
    return {
        "state": "active" if active else "ended",
        "org_id": row["org_id"],
        "expires_at": expires.isoformat(),
        "hours_left": round(secs_left / 3600, 1),
        "seconds_left": secs_left,
    }

def _trial_active(telegram_id: int) -> bool:
    return DEMO_ONLY and _demo_trial_state(telegram_id).get("state") == "active"
```

**Центральный гейт** (заменяет повторяющийся `_is_demo_user(user) or org_id ==
"demo-org-1"` ВО ВСЕХ ~26 аналитических эндпоинтах):
```python
def _use_demo_data(user: Dict, org_id: str) -> bool:
    """Отдавать ли демо-сэмпл вместо реальных данных.
    - явный demo-org-1 → всегда демо;
    - демо-юзер БЕЗ активного триала → демо;
    - демо-юзер С активным триалом → НЕ демо (его реальные данные)."""
    if org_id == "demo-org-1":
        return True
    return _is_demo_user(user) and not _trial_active(user.get("id", 0))
```
Замена в каждом из ~26 мест:
`if _is_demo_user(user) or org_id == "demo-org-1":` → `if _use_demo_data(user, org_id):`

Поведение после замены:
- **Триал active:** фронт шлёт РЕАЛЬНЫЙ org_id (не demo-org-1) → `_use_demo_data`
  = False → эндпоинт идёт обычным путём `_get_org_id`/`_get_restaurant_info`
  (реальный филиал юзера уже в БД) → отдаёт РЕАЛЬНЫЕ данные.
- **Триал ended / none:** `_use_demo_data` = True → демо-сэмпл (безопасно, реальные
  данные не текут после окончания).

> ВАЖНО: `_is_demo_user` в НЕ-аналитических местах НЕ трогаем (write-зарплаты,
> setup_validate, demo-лимит накладной) — там гейт остаётся строгим.

### 3. Старт триала при подключении (api.py, `_handle_demo_registration`)

После успешного `add_restaurant(...)`:
```python

```
И сообщение в чат (вместо/в дополнение к текущему «✅ iiko подключён»):

### 4. Подсказки в чат-регистрации (api.py, `DEMO_REG_PROMPTS`)

- **server:** «Адрес iiko-сервера — это адрес, по которому вы открываете iikoWeb/

  после проверки.»

### 5. Статус триала для фронта (api.py)

`/api/config` без авторизации — не годится для per-user. Новый authed-эндпоинт:
```python
@app.get("/api/demo/trial")
async def demo_trial(user: Dict = Depends(get_current_user)):
    if not DEMO_ONLY:
        return {"state": "disabled"}
    st = _demo_trial_state(user.get("id", 0))
    # org_id для фронта, чтобы грузить реальный филиал во время триала
    return st
```

### 6. Фронт (index.html)

`initApp`, ветка демо-бота (`demoOnly === true`) — вместо безусловного
`startDemo()`:
```js
const trial = await apiGet('/api/demo/trial');  // {state, org_id, seconds_left, ...}
if (trial.state === 'active') {
  await enterTrialMode(trial);     // грузим РЕАЛЬНЫЙ филиал + баннер с обратным отсчётом
} else if (trial.state === 'ended') {
  showTrialPaywall();              // полноэкранный замок + апселл, приложение заблокировано
} else {
  startDemo();                     // как сейчас — демо-сэмпл
}
```

- **`enterTrialMode(trial)`**: ведёт как обычный подключённый юзер — `checkExistingUser()`
  (грузит реальные рестораны через `/api/restaurants`, которые на демо-боте теперь
  вернут его филиал), `state.demoMode = false`. Сверху — **баннер**: «⏳ Демо-доступ к
  вашим данным: осталось Хч Ymин» с живым отсчётом (из `seconds_left`). Баннер всегда
  виден, при истечении (клиентский таймер дошёл до 0) → `showTrialPaywall()`.
- **`showTrialPaywall()`**: новый полноэкранный экран `#screen-trial-end`, перекрывает
  навбар/контент. Текст: «⏳ Ваш 24-часовой доступ к данным закончился.» + оффер (см.
  ниже) + кнопка «💬 Подключить — написать менеджеру» (t.me/wiregroup). Кнопок выхода в
  аналитику нет — жёсткий замок.

### 7. Оффер / цены (копирайт)

Новая структура: **разработка/подключение 200 000 ₸ + подписка</** (помесячно).

в спеке зафиксировано 30 000 ₸/мес как у текущего «первым 5»):

## Безопасность / приватность

- Реальные iiko-доступы хранятся шифрованно (`add_restaurant` → Fernet) в БД
  демо-сервиса — как и раньше.
- После окончания триала бэкенд перестаёт отдавать реальные данные
  (`_use_demo_data` → демо), фронт показывает пейволл. Реальные цифры не текут
  после 24ч.
- Триал не сбрасывается повторным подключением (`INSERT OR IGNORE`) — нет вечного
  бесплатного доступа.

## Вне объёма (YAGNI)

- Напоминание в боте «остался 1 час доступа» (можно v2, фоновой задачей).
- Продление/повторный триал, промокоды.
- Серверный жёсткий запрет на отрисовку после истечения сверх того, что уже даёт
  `_use_demo_data` (фронт-замок + бэк-возврат к демо достаточно).
- Реальный фудкост для самохостед — недоступен (лицензия iiko), в триале честно
  покажет «недоступно» (фикс A3).

## Критерии готовности

- Демо-юзер подключает iiko в чате (с подсказками) → бот стартует 24ч-триал и зовёт
  открыть Mini App.
- В течение 24ч Mini App показывает РЕАЛЬНЫЕ данные его филиала на вкладках, сверху —
  баннер с обратным отсчётом.
- Через 24ч (и при заходе после) — полноэкранный замок с оффером (200 000 ₸ разработка
  + подписка) и кнопкой менеджера; в аналитику не пускает.
- Повторное подключение/перезаход не продлевает триал.
- Не-демо (основной бот) и строгие гейты (зарплата, setup) не затронуты.
- Самохостед: реальны выручка/чек/блюда/смены; фудкост-% — «недоступно».
