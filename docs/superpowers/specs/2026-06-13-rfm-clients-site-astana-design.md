# Сайт «RFM-клиенты · Астана» — дизайн

Дата: 2026-06-13
Репозиторий: `iiiko` (сервис `iiko`, FastAPI + iikoServer)

## Цель

Отдельная веб-страница (свой URL) с полной картиной по клиентам **всех филиалов Астаны**: RFM-сегментация по правилам из Obsidian-заметок + выписанные идеи из «Тактика». Открывается по ссылке (для просмотра/презентации, в т.ч. инвесторам — vault называется «Invest»).

## Не входит (YAGNI)

- Не трогаем вкладку «Клиенты» в Mini App и её `_compute_rfm` (квинтили) — это отдельная логика.
- Не показываем индивидуальные телефоны/клиентов — только агрегаты по сегментам и филиалам.
- Не строим запись/кампании — это витрина аналитики + идеи, не инструмент рассылок.

## Доступ

- Открывается по ссылке с токеном: `GET /rfm?key=<СЕКРЕТ>`.
- Секрет — из env `RFM_SITE_KEY`. Если env пуст → роут отдаёт 404 (не светим существование). Если `key` не совпадает → 403.
- Без Telegram-авторизации (ссылку можно дать инвестору).

## Данные и филиалы

- Филиалы Астаны = `get_all_restaurants()`, отфильтрованные по `organization_name`, начинающемуся со слова «Астана» (учесть «Астана,» / «Астана ») — 9 точек.
- По каждому филиалу: `get_client(api_login, iiko_server, api_password)` → `olap_clients_rfm(dept, date_from, date_to)`.
  - `dept` = `rest["organization_name"]`. Для self-hosted iikoServer OLAP-фильтр `Department` принимает **название** филиала (подтверждено `_olap_dept`: при заданном `iiko_server` возвращает `org_name`). `get_all_restaurants()` отдаёт поле `organization_name` с расшифрованным `api_password` — `user`-контекст не нужен.
- Окно: последние **180 дней** (`date_to = сегодня`, `date_from = сегодня−180д`). Нужно >90 дней, чтобы видеть R у «уснувших».
- Строки `olap_clients_rfm`: `{"Delivery.CustomerPhone", "OpenDate.Typed", "UniqOrderId.OrdersCount", "DishDiscountSumInt"}`.

### Агрегация по клиенту (новая, с разбивкой по 90д)

Для каждого телефона собрать:
- `last_date` — максимальная `OpenDate.Typed`.
- `orders_90`, `spend_90` — сумма заказов/выручки за последние 90 дней.
- `orders_total` — заказов за всё окно (180д) — для выявления «раньше частых».
- Привязка к филиалу: для пер-филиальной таблицы держим агрегат и по `(branch, phone)`.

Телефон нормализуем (как `_norm_phone`), пустые/служебные отбрасываем.

## RFM по правилам заметки (`A. RFM-движок на iiko`, `Сегменты RFM`)

Новая функция `_rfm_by_thresholds(agg, today)` — НЕ квинтильная `_compute_rfm`.

**Бакеты (как в заметке):**
- **R** = дней с `last_date`: `0–14 / 15–30 / 31–60 / 61–90 / 90+`.
- **F90** = заказов за 90 дней: `1 / 2–3 / 4–6 / 7+`.
- **M** = квинтиль `spend_90` по базе клиентов (5 = топ).

**Сегменты — упорядоченные правила (первое подходящее):**
1. 🏆 **Champions** — `R ≤ 30` И `F90 ≥ 4` И `M-квинтиль ≥ 4`. *(R↑F↑M↑)*
2. 💛 **Loyal** — `R ≤ 30` И `F90 ≥ 2` (и не Champion). *(F↑M↑)*
3. 💸 **Big spenders, редкие** — `M-квинтиль ≥ 4` И `F90 ≤ 2` И `R ≤ 60`. *(F↓M↑)*
4. 🌱 **New / Promising** — `R ≤ 30` И `F90 = 1`. *(R↑F↓)*
5. 😴 **At-risk** — `R 31–90` И `orders_total ≥ 3` (раньше частый, окно открыто). *(R↓ F↑ в прошлом)*
6. ⚰️ **Lost / Hibernating** — всё остальное (`R > 90`, либо лапснувший с низкой частотой). *(R↓F↓)*

Метаданные сегмента (emoji, label, **действие**, **пример сообщения**) — из таблицы «Тактика · Часть 2» и «Сегменты RFM».

`_rfm_by_thresholds` возвращает:
```
{ "total": N,
  "segments": [ {key, emoji, label, count, pct, revenue, action, example} ... ]  # только непустые
}
```

## Структура страницы (server-rendered HTML)

Рендерится функцией `_render_rfm_html(report)` → `HTMLResponse`. Самодостаточный HTML (inline CSS), тёмная аккуратная вёрстка под мобайл/десктоп.

1. **Шапка:** «RFM клиентов · филиалы Астаны», подпись «доставка iiko · последние 180 дней · <дата>».
2. **KPI-строка:** клиентов всего · выручка с клиентов · средний LTV · % повторных (2+ заказа).
3. **Карточки сегментов** (по правилам выше): emoji + label · `count` · `pct%` · `выручка` · строка **«→ что делать»** (action) · курсивом пример сообщения.
4. **Таблица по филиалам Астаны:** строка на филиал — клиентов / выручка / % повторных / ср. LTV (сортировка по выручке). *(Champions по филиалу не выводим: M-квинтиль считается по общей базе, пер-филиальный квинтиль вводил бы в заблуждение.)*
5. **Блок «Идеи (из заметки Тактика)»** — выписано полностью:
   - **Уснувшие VIP** + правило «персональный подход, не скидка» + **лестница возврата** (день 30/45/60).
   - **Таблица «сегмент → действие → пример сообщения»** (8 строк из Тактики).
   - **Челленджи** (стрик, суши-пятница, коллекция, личный, реферальный, сезонные, mystery box, уровни).
   - **Миграция в приложение** (пряники + каналы захода + экономика push vs WhatsApp).

Тексты идей берутся дословно из `Тактика — сегменты, челленджи, приложение.md` (вшиваются в шаблон как статический контент).

## Код

- `api.py`:
  - `from fastapi.responses import HTMLResponse` (добавить к импортам).
  - `RFM_SITE_KEY = os.getenv("RFM_SITE_KEY", "")`.
  - `_astana_restaurants()` → list из `get_all_restaurants()` с `organization_name`, начинающимся на «Астана».
  - `_rfm_by_thresholds(agg, today)` — сегментация по заметке (см. выше).
  - `_render_rfm_html(report)` — сборка HTML-строки.
  - `@app.get("/rfm")` `async def rfm_site(key: str = "")` — проверка ключа → сбор данных по филиалам Астаны → агрегат → `_rfm_by_thresholds` + пер-филиальная статистика → `HTMLResponse(_render_rfm_html(...))`.
- `iiko.py` — без изменений (используем существующий `olap_clients_rfm`).
- `render.yaml`/env — добавить `RFM_SITE_KEY` (вне репо задаётся значение).

## Приватность

- Только агрегаты (counts, %, выручка по сегментам/филиалам). Телефоны и отдельные клиенты НЕ выводим.
- Роут за токеном; при пустом `RFM_SITE_KEY` — 404.

## Тестирование

- `_rfm_by_thresholds`: синтетический `agg` с заранее известными R/F90/M/orders_total → проверить попадание в каждый из 6 сегментов и корректные count/pct/revenue.
- Роут `/rfm`: без `key` (при заданном env) → 403; неверный `key` → 403; при пустом env → 404. (Данные iiko в юните мокаем/или проверяем только ветку доступа.)
- Нормализация телефона: пустые/служебные отбрасываются (повторно используем `_norm_phone`).

## Открытые допущения (зафиксированы)

- M-квинтиль считается по `spend_90` среди клиентов с `orders_90 ≥ 1`; клиенты без заказов за 90д (только лапснувшие, R>90) в M-квинтиль не входят и попадают в Lost/Hibernating.
- «Филиал Астаны» определяется по префиксу имени; если появится филиал вне Астаны с таким именем — поправить фильтр.
