# Дизайн: «Бумага» + движок целей

Дата: 2026-07-19
Статус: спека на ревью

## 1. Зачем

Две связанные работы:

1. **Визуальный язык.** Текущий сайт (`web/`) — типовой тёмный дашборд: одна карточка на всё, ровная сетка, дефолтные графики. Иерархии нет: убыток 2,9 млн ₸ и «открытых заказов: 8» весят одинаково.
2. **Движок целей.** Продукт показывает lag-метрики (выручка, чек, фудкост) — то, на что владелец не может нажать напрямую. Ценность появляется, когда данные превращаются в 2–3 контролируемых действия на неделю.

Обе упираются в один принцип из `01 — Концепция`: **нет числа в тенге — инсайт не показываем.**

## 2. Дизайн-язык «Бумага»

Выбран из трёх направлений (см. `.superpowers/brainstorm/`). Светлый финансовый отчёт вместо тёмного дашборда.

### Токены (`web/src/index.css`)

```
--paper      #faf7f2   фон
--paper-2    #f2ede4   зебра таблиц, вложенные блоки
--ink        #17171a   текст, столбики графиков
--ink-2      #57544c   вторичный текст
--muted      #8b8574   подписи капсом
--rule       #ded8cc   линейки
--rule-hard  #17171a   тяжёлая линейка под шапкой
--neg        #c8562f   потери, падение
--pos        #2f7a52   рост
--warn       #b8860b   внимание
```

`--pos` / `--warn` / `--neg` — это ровно 🟢🟡🔴 светофора из `01 — Концепция`. Один набор цветов на оба смысла.

Тема только светлая. Токены объявляются CSS-переменными, чтобы тёмную можно было добавить позже без переделки компонентов.

### Типографика

| Роль | Гарнитура | Где |
|---|---|---|
| Геройские цифры, заголовки от 22px | **Playfair Display** 400/500 | только крупный кегль |
| Интерфейс, подписи, текст | **Golos Text** 400/500/600/700 | везде |
| Цифры в таблицах | **JetBrains Mono** + `tabular-nums` | только таблицы |

Роли жёсткие. Playfair в таблице ломает выравнивание колонок — это ошибка, а не вкусовщина.

### Структура

Карточек нет. Форму держат линейки и сетка. Скругления: 0 на структуре, 4px на кнопках и полях. Исключение — виджет на телефоне: он лежит на домашнем экране, там 15px.

Графики recharts перекрашиваются: чернильные столбики, выделение `--neg`, волосяная базовая линия, оси в Golos 9px, без сетки.

## 3. Информационная архитектура

Плоский список из 8 пунктов → группы:

- **СВОДКА** — Аналитика, Главная
- **ЦЕЛЬ** — цель недели и её выполнение *(новое)*
- **ДЕНЬГИ** — Фудкост, Расходы, Год к году
- **ОПЕРАЦИИ** — Смены, Аномалии
- **ОЦЕНКИ** — Отзывы *(+ Соцсети, Персонал, Меню — позже)*

## 4. Три шаблона экрана

Чтобы 8+ экранов не стали 8 разными дизайнами:

- **Разбор** — герой-цифра, фраза-интерпретация, секции через линейки. Аналитика, Главная.
- **Реестр** — плотная таблица, моно-цифры, инлайн-бары, сортировка. Фудкост, Расходы, Смены, Аномалии, Год к году.
- **Оценка** — балл, из чего сложился, тренд, доказательства. Отзывы, позже остальные оценки.
- **Табло** — цель, полоса прогресса lag, список lead-действий с галочками, кнопки решения. Экран «Цель» и оба виджета.

Правило тенге зашивается в типы: строка инсайта без денежного значения не собирается компилятором.

## 5. Движок целей

### Модель

- **Цель (lag)** — одна за раз, с baseline из их же истории, целевым значением и дедлайном. «Средний чек 14 759 → 16 500 за 6 недель».
- **Действия (lead)** — 2–3 штуки, контролируемые на этой неделе, обязательно измеримые из уже имеющихся данных.
- **Табло** — прогресс lag + галочки lead, видно за один взгляд.
- **Недельный ритм** — диагноз → предложение → принятие → трекинг → закрытие.

Одна цель, не десять. Если движок предлагает больше одной — это баг.

### Неймспейс

`/api/plan` **занят**: это план/факт по трём корзинам из Google-таблицы клиента, к целям отношения не имеет. Новая фича живёт под **`/api/goal/{org_id}`** (GET текущая, POST принять/поправить/отложить).

Генератор — расширение `insights_service.py` (`gather` → `compute` → `ai_narrate`), не второй сервис рядом.

### Карта: метрика → цель → lead-действие → источник

| Разрыв | Lead-действие | Эндпоинт |
|---|---|---|
| Средний чек ниже baseline | доля чеков с допником | `/api/sales` |
| Фудкост выше нормы | меню-инжиниринг по техкартам | `/api/foodcost` |
| Списания | удержать списания ниже порога недели | `/api/writeoffs` |
| Отмены | удержать отмены ниже порога смены | `/api/cancels` |
| Провальные часы | промо на мёртвое время | `/api/load-heatmap`, `/api/chaspik` |
| Расписание не под трафик | смены по прогнозу, а не по привычке | `/api/salary` + `/api/load-heatmap` |
| Дрейф закупочных цен | пересмотр поставщика | `/api/price-stats` |

### Prime cost — мастер-светофор

`(фудкост + ФОТ) / выручка`, из `/api/foodcost` и `/api/salary`. Норма 55–65%. Выше 65% — структурная проблема, и движок обязан разбирать в порядке: расписание → меню-микс → фудкост. Это верхний светофор на «Главной».

Бенчмарки — ориентир «куда», baseline из их истории — точка «откуда». Цель не ставится от бенчмарка в отрыве от их реальности.

Пороги lead-действий движок считает от baseline филиала (медиана за 8 недель), а не берёт из констант. Цель обязана быть достижимой за срок: недостижимую владелец бросает после первой недели.

## 6. Виджеты

Веб-вьюхи в том же приложении, открываются с телефона и из шортката.

- **`/w/owner`** — выручка, дельта, фудкост, prime-cost-светофор, одна строка утечки в тенге.
- **`/w/staff`** — цель смены, прогресс, lead-галочки, фотоконтроль.

Нативный виджет Scriptable — отдельная работа (`05 — Игра для команды`), в этот объём не входит. Scriptable рисует нативно, а не HTML, поэтому это реализация того же языка, а не переиспользование вьюх.

## 7. Реальные данные вместо демо

`web/src/lib/api.ts` первой строкой держит `ORG = 'demo-org-1'` — весь фронт ходит в демо-организацию. Это и есть то, что делает сайт демо.

Нужно: выбор организации, проброс авторизации, состояния «нет данных» и «организация не подключена» на каждом экране. Демо-режим остаётся как отдельный вход для продаж, но перестаёт быть единственным.

## 8. Фазы

Каждая получает свой план реализации отдельно.

1. **Язык** — токены, шрифты, `ui.tsx`, перекраска графиков, перевод 8 экранов.
2. **Реальные данные** — отвязка от `demo-org-1`, выбор организации, пустые состояния.
3. **Цели** — `/api/goal`, генератор поверх `insights_service.py`, экран «Цель», табло, недельный ритм через `/api/weekly-report`.
4. **Виджеты** — `/w/owner`, `/w/staff`.

Оценки (соцсети, персонал, меню-инжиниринг, сводный балл) — за пределами этой спеки. Место в вёрстке и навигации под них заложено.

## 9. Чего не делаем

- Тёмной темы.
- Нативного виджета и Live Activity.
- Nudge-уведомлений, обучающихся на паттернах: сначала недельный ритм на существующем дайджесте.
- Нескольких одновременных целей.
- Оценок как фичи.
