# Спека: ИИ-ассистент «Директор» — проактивный агентный советник

Дата: 2026-08-03 · Ветка: feat/paper-design · Статус: дизайн утверждён владельцем

## 1. Цель

Заменить текущего демо-агента (`web/src/lg/Agent.tsx`, захардкоженные `reply()` и
`TIPS`) на **проактивного ИИ-советника**, который сам анализирует **все филиалы**
владельца и выдаёт конкретные, действующие советы «проблема → сколько денег →
что сделать», с указанием филиала, времени и, где уместно, — **действия** в
интерфейсе (открыть вкладку, показать динамику, поставить смену).

Цель по бизнесу: помогать ресторанам **увеличивать прибыль** — не абстрактные
подсказки, а приоритезированный по деньгам план, который можно выполнить в один тап.

## 2. Не-цели (сейчас)

- **Не чат.** Убираем текстовый ввод/переписку. Ассистент проактивен + карточки-действия.
- **Не UI-полировка.** Живёт в существующем «мини-уголке» (персонаж снизу справа),
  сам всплывает с 1–2 важными карточками. Отдельной вкладки в меню нет. Красоту
  дорабатываем позже — сейчас главное начинка.
- **Не свободные вопросы** (Q&A) на старте — возможно, позже.
- Instagram/соцсети-вглубь — отдельная отложенная тема (не входит сюда).

## 3. Архитектура

### 3.1 Мозг — Claude поверх РЕАЛЬНЫХ цифр

Новый бэкенд-эндпоинт **`GET /api/assistant`** (scope: все филиалы владельца):

1. **Сбор сигналов** — переиспользуем логику существующих эндпоинтов, считаем по
   каждому филиалу владельца компактный набор фактов:
   - фудкост (`/api/foodcost` compute): fact_pct, покрытие, худшие блюда;
   - выручка и средний чек (`/api/dashboard`);
   - час-пик (`/api/load-heatmap`): день недели × час с максимумом загрузки;
   - отмены/возвраты (`/api/cancels`), списания (`/api/writeoffs`);
   - стоп-лист (`/api/stoplist`);
   - отзывы/Wolt/2ГИС (`/api/reviews`): рейтинг и динамика;
   - явки/недоукомплектованность (`/api/attendance`) — сопоставить с час-пиком.
2. **Грудинг:** все числа уже посчитаны нами и передаются Claude как факты.
   Системный промпт запрещает выдумывать числа — только оперировать данными.
   Claude **рассуждает и формулирует**, деньги/проценты берёт из фактов.
3. **Вызов Claude** с описанием набора действий (tool-подобная схема, см. 3.2).
   Модель и параметры — подобрать по правилам скилла `claude-api` на этапе кода
   (из головы не фиксируем; по умолчанию — актуальная и способная модель Claude).
4. **Ответ** — структурированный JSON: список советов
   ```
   Advice = {
     id: string,
     branch: string,          // название филиала («Актобе, …») или «Все филиалы»
     severity: 'high'|'med'|'low',
     title: string,           // «Пт–Сб пик 19:00–23:00 — не хватает официантов»
     detail: string,          // короткий разбор по реальным цифрам
     money: number | null,    // ₸/мес эффекта, из фактов
     action?: Action          // опциональное действие (см. 3.2)
   }
   ```
   Сортировка — по деньгам/важности. Отдаём топ-N (например, 5) + признак,
   сколько ещё.

### 3.2 Действия (MCP-подобные инструменты)

Фиксированный набор на старт (Claude выбирает и заполняет параметры):

- **`navigate`** `{ tab: SectionId }` — открыть вкладку (через существующий
  `window.dispatchEvent('lg:go', tab)`).
- **`showMetric`** `{ tab: SectionId, hint?: string }` — открыть вкладку и
  подсветить нужный показатель (навигация + маркер).
- **`proposeShift`** `{ branch, employeeName?, date, start, end }` — раскрывает
  **карточку-действие**: сотрудник (выпадашка со списком явок филиала), дата,
  время — предзаполнено Claude, владелец правит и жмёт «Поставить».
  Запись — в план расписания (**localStorage**, тот же путь, что ручной
  `CellEditor` в `Schedule.tsx`: `setShift({employeeId, date, start, end})`).

Действия — «белый список»: фронт исполняет только известные типы, произвольный
код Claude не запускается.

### 3.3 Фронтенд

- Переписываем `Agent.tsx`: убрать `reply()`/чат-инпут и захардкоженные `TIPS`.
- При открытии приложения ассистент запрашивает `/api/assistant`, кэш ~15 мин.
- Персонаж проактивно всплывает тостом с **1–2 самыми важными** советами.
- Тап по персонажу → панель со списком советов (все филиалы, по деньгам) +
  кнопки-действия. Действие `proposeShift` разворачивает карточку с полями.
- Загрузка/ошибка LLM — честный статус (не демо): «Собираю сигналы…» /
  «Не удалось собрать советы» + фоллбэк (см. 5).

## 4. Поток данных

```
open app / open assistant
  → GET /api/assistant  (бэк собирает сигналы по всем филиалам)
      → сформировать факты  → вызвать Claude (+ схема действий)
      → распарсить советы[]  → кэш
  → фронт рендерит топ-2 тостом + полный список по тапу
  → тап действия:
      navigate/showMetric → переключить/подсветить вкладку
      proposeShift → карточка (сотрудник/дата/время) → «Поставить» → localStorage
```

## 5. Ошибки и фоллбэк

- Claude недоступен/таймаут/невалидный JSON → **фоллбэк на правила**: отдать
  топ-задачи из уже существующего движка «деньги÷усилие» (логика `Director.tsx`
  `tasks`, вынесенная в общий модуль), чтобы советы были всегда, пусть шаблонные.
- Нет данных у филиала (не заполнены техкарты и т.п.) → совет = план «заполни X»
  (тот же принцип `PlanFallback`), а не пустота/0.
- Записи (смены) — только по тапу «Поставить»; клиентские, откатываемые.

## 6. Многофилиальность

Ассистент смотрит все филиалы владельца, называет проблемный («в Актобе фудкост
поплыл», «Wolt просел у всех»). Сбор сигналов — параллельно по филиалам с
таймаутами; медленный/упавший филиал не блокирует остальные.

## 7. Стоимость/каденс

1 вызов Claude на обновление, обновление при открытии ассистента + кэш ~15 мин
(и/или фоновый пересчёт раз в N минут). Не дёргать LLM на каждое действие.

## 8. Тестирование

- Юнит: парсинг ответа Claude в `Advice[]`, валидация действий по белому списку,
  фоллбэк-движок правил (детерминированный, тестируется без сети).
- Сбор сигналов: мок эндпоинтов, проверка компактного факт-пейлоада.
- Действие `proposeShift`: запись в localStorage совпадает с ручным `CellEditor`.
- Грудинг: тест, что при подмене данных числа в советах меняются (не захардкожены).

## 9. Фазы

- **Ф1 (начинка):** `/api/assistant` (сбор сигналов + Claude + схема действий),
  переписанный `Agent.tsx` на реальные советы, действия navigate/showMetric,
  фоллбэк-правила. UI — минимальный, в существующем уголке.
- **Ф2:** действие `proposeShift` (карточка + запись в расписание).
- **Ф3 (позже):** UI-полировка, возможно свободные вопросы (Q&A).
