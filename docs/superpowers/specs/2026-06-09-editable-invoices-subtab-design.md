# Редактируемые накладные в суб-вкладке «Накладные»

Дата: 2026-06-09
Статус: согласовано (брейншторм)

## Проблема

Сейчас бот после чат-распознавания и авто-сопоставления **сразу создаёт черновик
в iiko** (`status=draft_in_iiko`) и кладёт его в суб-вкладку «Накладные». В суб-вкладке
для такой накладной доступна только кнопка «▶️ Провести». Если оператор ошибся в
**филиале** или **поставщике** (а это частая ошибка при чат-сопоставлении) — исправить
уже нельзя: приходится заново пробивать накладную через чат.

Прямое редактирование «уже созданного в iiko» черновика невозможно безопасно:
- повторный импорт с тем же `documentNumber` → iiko отдаёт 409 (конфликт);
- импорт с новым номером → дубликат черновика;
- безопасного API удаления документа в коде нет.

## Решение (review-first)

Сдвигаем момент создания в iiko: бот больше **не** создаёт черновик в iiko сразу.
Он сохраняет **локальный** черновик со статусом `ready` (все позиции уже
сопоставлены) и просит открыть Mini App. Оператор в суб-вкладке правит
филиал / поставщика / дату / позиции, и только по кнопке **«Создать черновик в iiko»**
накладная уходит в iiko (первый и единственный раз → дублей и сирот нет).

Уже существующие `draft_in_iiko` остаются как есть — их редактирование вне scope
(правятся в самом iiko). Потоки `needs_mapping` / `iiko_error` сохраняют текущую
кнопку «✏️ Сопоставить и отправить» (тот же редактор).

## Изменения

### Backend (`api.py`, `iiko.py`)

1. **`_auto_match_items` (api.py ~3336)** — при успешном матче дописывать в сам объект
   позиции `it["iiko_product_id"]` и `it["iiko_product_name"]` (мутация на месте).
   Сейчас функция возвращает только `sendable`, а исходные `items` остаются без id —
   из-за этого сохранённый локальный черновик «теряет» сопоставление. После правки
   сохранённые `items` несут маппинг, и редактор показывает «✓ сопоставлено», а
   последующая отправка в iiko собирает `sendable` из тех же `iiko_product_id`.
   (Заодно чинит частичный матч в ветке `needs_mapping`.)

2. **`_finalize_send` (api.py ~3639–3697)** — заменить блок «создание в iiko» на
   сохранение локального черновика:
   - `save_bot_invoice(..., status="ready")` с `supplier_id`, `organization_id`,
     `branch=rest["organization_name"]`, аннотированными `items`.
   - Текст в чат: `✅ Накладная готова. Открой Mini App → Расходы → Накладные,
     проверь филиал/поставщика и нажми «Создать черновик в iiko».`
   - Старый dedup и ветка `needs_mapping` не трогаются.

3. **`BOT_STATUS_MAP` (api.py ~1434)** — добавить `"ready": "Готова — проверь"`.

4. **`SavedInvoicePayload` (api.py ~2603)** — добавить опциональные
   `supplier_id: Optional[str]` и `organization_id: Optional[str]`.

5. **`invoice_saved_send` (api.py ~2611)** — принять и применить смену филиала/поставщика:
   - если в payload пришли `supplier_id` / `organization_id` — записать их в
     `update_fields` и использовать как `org_id`/`supplier_id` для отправки
     (вместо чтения только из БД-записи);
   - остальная логика (build sendable из `iiko_product_id`, отправка, перевод в
     `draft_in_iiko`) уже есть и переиспользуется без изменений.
   - При смене филиала на другой iiko-сервер `iiko_product_id` могут оказаться
     невалидны → `create_incoming_invoice` вернёт ошибку, она показывается оператору
     (без тихой порчи данных). Это известное ограничение, не решаем сейчас.

6. `invoice_saved_get` уже возвращает `supplier_id` и `organization_id` — менять не нужно.

### Frontend (`index.html`)

7. **Список накладных (~2942–2972)** — добавить ветку: `raw_status === 'ready'`
   (а также `'needs_mapping' || 'iiko_error'`) → кнопка
   `✏️ Редактировать` → `openSavedInvoiceEditor(inv.bot_id)`.
   `draft_in_iiko` / `posted` / старый поток — без изменений.

8. **Редактор `screen-invoice-edit` (~1294–1316)** — в блок `.ie-meta` добавить:
   - **Филиал**: `<select id="ie-branch">`, наполняется из `/api/restaurants`
     (`{org_id, org_name}` из ответа). `onchange` → перезагрузить поставщиков и
     сбросить выбранного.
   - **Поставщик**: заменить free-text `#ie-supplier` на поле поиска
     `#ie-supplier-search` + выпадашка результатов `#ie-supplier-results`.
     Список грузится один раз через `/api/suppliers/{org_id}` (`{id, name}`),
     фильтрация по подстроке — **на клиенте** (поиск по названию). Выбор пишет
     `ieState.supplierId` + показывает имя.

9. **JS состояние/логика**:
   - `ieState` += `branches`, `suppliers`, `supplierId`, `supplierName`.
   - `openSavedInvoiceEditor`: после загрузки накладной — `await` загрузка
     `/api/restaurants`, заполнить `<select>` (выбрать текущий `data.organization_id`),
     загрузить поставщиков текущего org, выставить текущего `data.supplier_id`/имя.
   - `ieSearchSuppliers()` — debounce-фильтр по `ieState.suppliers`.
   - `iePickSupplier(s)` — пишет `supplierId`/`supplierName`, закрывает выпадашку.
   - `ieChangeBranch()` — на смену `<select>`: обновить `ieState.searchOrgId`,
     перезагрузить поставщиков, очистить выбранного поставщика.
   - `ieSave` (ветка `savedBotId`): добавить в payload
     `supplier_id: ieState.supplierId`, `organization_id: ieState.searchOrgId`.
   - Текст кнопки сохранения для `ready`: **«💾 Создать черновик в iiko»**
     (для `needs_mapping`/`iiko_error` оставить «💾 Сопоставить и отправить»).

10. **Фикс клавиатуры (CSS `.ie-modal-back` ~486)** — модалка редактирования позиции
    сейчас нижний лист (`align-items:flex-end`), поэтому экранная клавиатура при
    поиске по номенклатуре перекрывает поле и выпадашку результатов. Менять на
    привязку к **верху** (`align-items:flex-start`) + небольшой отступ сверху, чтобы
    поле «Название» и результаты всегда были над клавиатурой. Поля кол-во/цена/кнопки
    остаются ниже (во время поиска не нужны). Скругление — со всех сторон.

## Что НЕ делаем (scope)

- Редактирование уже созданных в iiko черновиков (`draft_in_iiko`) — нет безопасного
  удаления/перезаписи.
- Перенос/удаление документа между филиалами в iiko.
- Пересопоставление позиций при смене филиала на другой сервер (ошибка просто
  показывается).

## Проверка

- Бот: фото → распознавание → чат сообщает «готова», в iiko ничего не создано,
  в суб-вкладке появилась накладная `Готова — проверь` с кнопкой «✏️ Редактировать».
- Редактор: смена филиала перезагружает список поставщиков; поиск поставщика
  фильтрует по названию; дата меняется; «Создать черновик в iiko» → статус
  становится «Создан в iiko», появляется «▶️ Провести».
- Клавиатура: при тапе в «Название» поле и результаты поиска остаются видимыми
  над клавиатурой.
